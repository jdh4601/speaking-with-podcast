# 회화 리포트와 자주 틀리는 표현 복습 설계

## 의도

사용자는 Preply 같은 1:1 영어 회화를 마친 뒤 화자 구분 스크립트를 얻는다. 지금은 이 기록을 학습으로 연결할 곳이 없다. 스크립트를 붙여 넣으면 실수를 교정해 보여주고, 회차별 수치로 실력 변화를 확인하며, 반복되는 실수를 대시보드에서 바로 복습하게 한다.

## 목표

1. 스크립트를 붙여 넣으면 본인 발화의 실수를 분석한 리포트를 만든다.
2. 실수는 빨간 형광펜으로 표시하고, 바로 아래에 개선 문장과 한글 해석을 둔다.
3. 회차별 수치와 변화를 그래프로 보여준다.
4. 반복되는 실수의 유형과 표현을 빈도수로 추적한다.
5. 대시보드의 가장 잘 보이는 왼쪽 영역에서 자주 틀리는 표현을 복습한다.
6. 대시보드 상단 통계와 하단 8주 로드맵을 없애고, 오늘 할 일을 하단에 작게 둔다.
7. 분석 버튼 한 번으로 그 수업의 단어를 `단어 · 뜻 · 예문` 표로 함께 정리한다.

## 비목표

- 발음 점수: 녹음이 없으므로 만들지 않는다.
- 녹음 파일 처리, 아이폰 연동, Speak 같은 앱의 통계 입력
- 팟캐스트 표현 복습(오른쪽 영역)의 동작 변경
- `dist/` 이전 웹 대시보드 변경

## 금지 사항

- 실제로 나빠진 회차를 좋아진 것처럼 보이게 하는 표시
- 스크립트에 없는 문장을 "내가 말한 문장"으로 표시하는 것
- 받아쓰기 오류로 의심되는 부분을 실수 빈도에 포함하는 것
- 회화 기록을 저장소에 커밋하는 것 (`AGENTS.md`의 개인 학습 기록 규칙)

## 접근법

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| Mac 앱에 회화 리포트 화면 추가 | 요청한 표시를 그대로 구현하고, 수치를 코드로 계산하며, 대시보드 복습과 연결된다 | 작업량이 크고 분석마다 Codex 사용량을 소비하며 아이폰에서 볼 수 없다 | **사용자 선택** |
| `english-conversation-review` 스킬 확장 | 앱 수정 없이 가장 빠르다 | 매번 Claude Code를 열어야 하고 형광펜·그래프 표현에 제약이 있다 | 제외 |

## 화면

### 대시보드 (`macos/web/index.html`)

- 제거: 상단 `.stats`, 주간 일정 `.calendar`, 하단 `.roadmap`, 왼쪽 패널의 진행 막대·할 일 목록·이번 주 주제·메모 입력
- 왼쪽 패널: **자주 틀리는 표현 복습**
  - 위쪽에 가장 많이 틀린 유형 3개와 횟수를 표시한다.
  - 카드 앞면은 한글 해석을 보여주고 영어로 말하게 한다.
  - 답을 확인하면 내가 말한 문장(빨간 형광펜), 개선 문장, 규칙 설명을 보여준다.
  - 카드 순서는 유형 빈도가 높은 순서이고, 같으면 최근 실수가 먼저이다.
  - **다음 →** 으로 넘기고, **외웠어요**를 누른 카드는 복습 목록에서 뺀다. 이 표시는 기기의 `localStorage`에 저장하며 실력 수치에는 반영하지 않는다.
  - 기록이 없으면 회화 리포트로 가는 버튼을 보여준다.
- 하단 띠: 오늘 할 일을 체크박스·제목·시간만으로 한 줄에 작게 표시한다. 기존 체크 키 `주차-요일-순번`을 유지하므로 체크 기록이 그대로 이어진다.
- 헤더: **회화 리포트** 링크를 추가한다.
- 유지: 오른쪽 팟캐스트 복습, 계획 설정(오늘의 주차 계산에 필요)
- 기존 메모 값은 저장소에 남기지만 화면에는 표시하지 않는다.
- 좁은 화면 탭의 "할 일"은 "자주 틀리는 표현"으로 바꾼다.

### 회화 리포트 (`macos/web/conversation.html`, 새 페이지)

- 입력: 스크립트 붙여넣기, 날짜(기본값 오늘), **분석하기** 버튼, 진행 상태
- 추이: 회차별 지표 그래프와 직전 회차 대비 변화. 기록이 1회이면 기준선임을 표시한다.
- 반복 실수: 유형별 순위와 표현별 순위. 각 항목에 총 횟수, 등장한 회차 수, 최근 회차별 횟수를 표시한다.
- 회차 리포트: 회차를 선택하면 실수마다 아래 순서로 표시한다.
  1. 내 문장 (틀린 부분에 빨간 형광펜)
  2. 개선 문장
  3. 개선 문장의 한글 해석
  4. 유형과 한 줄 규칙 설명
- 단어 정리: 회차별로 `단어 | 뜻 | 예문` 표를 표시한다.
  - 7~10개를 고른다. 수업에서 상대가 알려준 표현, 본인이 묻거나 막힌 단어, 앞으로 다시 쓸 만한 표현을 우선한다.
  - 뜻은 한글로, 예문은 영어로 쓴다. 예문 안의 대상 단어만 강조색 기울임으로 표시한다.
  - 표현이 스크립트에 나온 것이어야 하며, 예문은 수업 맥락에 맞게 새로 작성할 수 있다.
- "발음 확인 필요"와 "받아쓰기 확인 필요"는 별도 구역에 두고 빈도에서 제외한다.
- 잘못 분석한 회차를 지우는 삭제 기능을 둔다.

## 데이터 흐름

1. 파서가 줄을 화자별로 나눈다. `(You)`가 붙은 화자가 본인이다. 없으면 오류로 안내한다.
2. 상대의 짧은 맞장구로 끊긴 본인 줄은 하나의 발화로 합친다.
3. 코드로 지표를 계산한다.
4. Codex에는 본인 발화와, 각 발화 바로 앞뒤의 상대 발화 1줄씩(각 최대 200자)만 보낸다. 앞줄은 문맥을, 뒷줄은 상대의 교정과 단어 설명을 담는다. 기존 `codex_json`의 격리 실행을 재사용하고 전사는 데이터로 취급한다.
5. 서버가 결과를 검증한다.
   - 내 문장(`sentence`)이 해당 본인 발화에 그대로 있고, 틀린 부분(`wrong`)이 그 문장 안에 있어야 한다. 없으면 버린다.
   - 유형은 고정 목록 안에 있어야 한다.
   - 단어 항목은 강조할 부분(`target`)이 예문에 그대로 있어야 한다. 없으면 버린다.
6. 검증을 통과한 결과를 저장한다. 원본 스크립트 전체와 상대 발화는 저장하지 않는다.

발화가 많으면 턴 단위로 나눠 순서대로 분석한 뒤 합친다. 같은 본인 발화의 해시가 이미 있으면 중복 회차로 거절해 빈도가 부풀지 않게 한다.

## 수치

코드로 계산하는 값:

- 본인 단어 수, 대화에서 본인이 말한 단어 비율
- 말 더듬·재시작 비율: 100단어당 um/uh/hmm 같은 군말과 `I— I` 같은 반복의 수
- 한 번에 이어서 말한 평균 단어 수: 맞장구만 있는 발화는 제외한다.
- 100단어당 실수 수: 실수 건수는 Codex 판단에서 오지만, 비율 계산은 코드가 한다.

점수는 합산하지 않는다. 가중치가 임의적이어서 변화의 원인을 가리기 때문이다. 변화 방향은 지표별로 "개선/악화/동일"로 표시한다.

실수 지표는 Codex 판단에 의존하므로 회차 간 편차가 있을 수 있다. 회화 주제와 받아쓰기 서비스가 바뀌어도 값이 달라질 수 있다. 화면에는 직전 회차뿐 아니라 그래프 전체를 함께 보여준다.

## 분류

유형은 고정 목록이다: 동사 조합, 관사, 단수·복수, 수일치, 시제, 비교·최상급, 전치사, 문장 구조, 단어 선택, 기타.

표현별 추적을 위해 Codex가 실수마다 짧은 영어 키(`pattern`, 예: `the same`, `had an interview`)를 낸다. 회차 사이에 키가 흩어지지 않도록 기존 키 목록을 프롬프트에 함께 보내 재사용하게 한다.

## 저장

- 경로: `~/Library/Application Support/English Routine/conversations/<uuid>.json`
- `/api/sessions`는 최상위 `*.json`만 읽으므로 하위 폴더 기록과 섞이지 않는다.
- 필드: `id`, `date`, `createdAt`, `contentHash`, `metrics`, `turns`(본인 발화), `mistakes`, `reviewFlags`, `vocabulary`(`term`, `meaning`, `example`, `target`)

## 코드 구성

- 새 파일: `macos/conversation_report.py`(파싱·지표·검증·저장·집계), `macos/test_conversation_report.py`, `macos/web/conversation.html`, `macos/web/conversation.js`, `macos/web/conversation.css`, `macos/web/mistake-review.js`, `macos/web/mistake-review.css`
- 수정: `macos/server.py`(API 연결), `macos/build.py`(복사 목록), `macos/web/index.html`, `macos/web/app.js`, `macos/web/style.css`, `ios/verify.py`(새 JS 검사), `macos/README.md`, `README.md`
- API: `GET /api/conversations`, `POST /api/conversation-analyze`, `POST /api/conversation-delete`. 기존 작업 큐를 따른다.

## 디자인 예외

`DESIGN.md`의 "빨강은 틀렸다는 처벌에 사용하지 않는다"는 아이폰 복습 화면 기준이다. 이번 빨간 형광펜은 사용자의 명시적 요청이므로 적용한다. 대신 연한 빨강 배경으로 표시하고 글자색은 유지해 가독성을 지킨다.

## 구현자가 정할 사항

- 그래프는 외부 라이브러리 없이 인라인 SVG로 그린다.
- 턴 분할 크기와 군말 목록의 세부 값
- `body`가 `overflow:hidden`이므로, 하단 띠를 포함한 레이아웃이 창 높이 안에 들어가도록 조정한다.
- 8주 계획이 끝난 뒤에는 기존 계산처럼 8주차로 고정하되, 요일은 실제 오늘 요일을 사용한다.

## 검증

- 단위 테스트: 파서, 턴 병합, 지표, 인용 검증, 유형 검증, 단어 예문 검증, 중복 거절, 빈도 집계
- 통합 검사: `python3 ios/verify.py`
- 실제 앱 빌드 후 오늘 스크립트를 첫 회차로 분석하고 화면을 확인한다.
